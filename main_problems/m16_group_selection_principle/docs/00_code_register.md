## 三、新制規則

```
格式：<記錄號><用途字母><序號>
用途字母：R 殘留項／F 不變量・形式項／D 數據缺口／C 一致性缺口

例：
  M16F1   M16 的不變量項 1
  M14R1   M14 的殘留項 1
  O171R3  O171 的殘留項 3
  P9D2    P9 的數據缺口 2
```

四條硬規則：

1. **禁裸前綴** —— `MR1`／`MF1` 不再使用（缺記錄號，必撞）
2. **禁 prime** —— 唔准 `F1′`；撤回項保留原號並標「撤回」，取代項取新號
3. **撤回不重用** —— `M16F1` 撤回後，`M16F1` 永久代表該撤回項，唔可以派給新問題
4. **正文不動** —— 已寫好的正文（`docs/01`–`docs/07`）保持原樣；新碼由本表映射，新文檔一律用唯一碼

## 五、審計檢查項

```bash
# 1. 裸前綴掃描（新文檔必為 0）
grep -rnE "\bM[RF][0-9]" <record>/docs/*.md | grep -vE "\b(M[0-9]+[RF][0-9]|O[0-9]+[RF][0-9]|P[0-9]+[RFCD][0-9])"

# 2. prime 掃描（新文檔必為 0）
grep -rn "′" <record>/docs/*.md | grep -E "[MOP][0-9]*[RF][0-9]′"

# 3. 跨記錄撞名（倉庫級必為 0）
#    ★ 判「定義」而非「提及」—— 跨記錄引用（如 M14 docs/38 舉例 M16F1）係合法，
#      撞名 = 同一碼在兩個記錄各有**不同定義**。掃定義行（表格／清單起始）：
for c in $(grep -rhoE "\b[MOP][0-9]+[RF][0-9]" */ --include="*.md" | sort -u); do
  n=$(grep -rlE "^\| *\`?$c\`? *\||^ *$c +[^（(]" */ --include="*.md" \
        | cut -d/ -f1 | sort -u | wc -l)
  [ "$n" -gt 1 ] && echo "COLLISION: $c defined in $n records"
done
```

**實測基線（2026-11-04）**：新碼 `M16F1`／`M16F2`／`M16F3`／`O171R1`–`O171R3` 各只在 1 個記錄**定義**（M14 `docs/38 §六` 只作引用示範，非定義）。剩餘 `MR1`／`MR2`／`MR3` 之雙重定義屬 grandfather，由兩份碼表映射，正文不改。
