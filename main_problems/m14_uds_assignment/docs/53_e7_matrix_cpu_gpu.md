判讀：


若需 GPU 側亦達 float64 精度：把 `gpu_op` 之 `PHI` 由 float32 改 float64（記憶體 ×2，7 模態 800 MB→1.6 GB，
本卡 3 GB 需先關閉其他佔用），預期飄移可壓至 ≤1e−15（未做，成本／收益見 §五）。

## 三、`E_8` 阻斷（量化，非取巧可繞）

```
E_8 需 9 模態（1+2·4）。C(52,9) = 3,679,075,400 態。

記憶體：float64 向量 27.4 GB；鏈需同時持有 φ_4^9、φ_5^9 ⟹ 54.8 GB > RAM 54 GB
        GPU 側：3 GB 卡，單一向量已超 9×
算力（實測 1.65e8 候選/s @12 核 CPU；GPU 1.7e9/s）：
        V^{9→9}  1.371e14  ⟹ CPU 9.6 日／GPU 22 時
        V^{9→7}  1.360e13  ⟹ CPU 1.0 日／GPU 2.2 時
        V^{7→9}  7.581e12  ⟹ CPU 12.8 時／GPU 1.2 時
合計 CPU ≈ 11.5 日；GPU ≈ 26 時（但 GPU 側記憶體不足，無法容納 27.4 GB 輸出）
```

補充：9 模態之 rank 表若要落地需 `C(52,9)×9×4 B = 132 GB` ⟹ 必須改為**即時 unrank**（可行，本鏈已備 `unrank_rows`），
故瓶頸純為三個 27.4 GB 向量之共存。

可行路線（未做，需另立記錄）：

```
① 分塊外存（out-of-core）散佈：把 9 模態輸出切 64 塊（每塊 430 MB）落碟，
   逐塊收集 ⟹ 源掃描 ×64 ⟹ 算力再乘 64 ⟹ 不可行
② 稀疏表示：若 φ_4^9 非零率 ~10%（估），稀疏向量約 1e9 × 12 B = 12 GB ⟹ 可行但需重寫全部算子
③ 更大記憶體：CPU 側 ≥128 GB RAM（三向量同時在場）或 GPU ≥64 GB VRAM ⟹ 直接可行（算力仍 22–230 時）
```
