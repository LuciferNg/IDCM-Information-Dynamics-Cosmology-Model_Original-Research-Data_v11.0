# docs/38 — 內部碼命名空間（禁止與全域 PID 同名）

**日期**: 2026-11-02
**性質**: 命名規範修正，無新計算。`N_trials = 0`。
**觸發**: 用戶指示「不建議 M14 內部用 `M` 作 PID」。

---

## 一、問題

本 O 早期（`docs/18 §六`）以 `M1`–`M4` 標記四項內部殘留；`docs/20 §九` 以 `P1`–`P4` 標記另四項。兩者**與全域 problem id 撞名**：

```
全域 PID：M1 … M15（本記錄自身即 M14）、P1 … P12（main_problems/pN_*）、O1 … O256
內部舊碼：M1–M4（本 O 殘留）｜P1–P4（本 O 殘留）   ← 同名不同物
```

實際已造成語義風險的例子：

```
`docs/33` 之「note → M4」指**全域 M4 記錄**（v9 (k,d) 補強）
`docs/18` 之「M4」指**本 O 內部殘留**（荷差異之最後可能來源）
同一字串，兩義 —— 讀者無法由字面判定。
```

## 二、規範（本 O 自此生效）

```
★ 內部碼一律「雙字母 ＋ 數字」，例：`MR1`、`MR2` …（M = M 系列，R = 殘留項）
禁單字母 ＋ 數字（`M1`、`P1`、`O1` ＝ 全域 PID，必撞）
禁點號式（`m14.1` 型）—— 小寫＋點號 與版本號／路徑／檔案副檔名同形，實測更易混淆
非 PID 字母之既有家族（N／Q／K／L／J／G／X）保留，但明示只在本 O 內有效
```

## 六、附註（2026-11-04，append-only）：裸雙字母仍會跨記錄撞名

§二 之 `MR1`–`MR8` 只解決了「與全域 PID 撞名」，**未解決「與其他記錄的內部碼撞名」**。實測：

```
M14  MR2 = 14 模子晶格之物理身份（本表 §三）
M16  MR2 = 深層 g = 60 之識別循環（420 = L₄·60，O171 docs/09 C1）
```

同一字串、兩個記錄、兩個唔相干問題。`grep -rn "MR2"` 得兩義，且 M16 那三個碼（`MR1`/`MR2`/`MR3`）其實係**上游 O171 的**殘留 —— 引用時無記錄號，形成三方混淆（O171 原義／M14 本地義／M16 引用義）。

### 新制（只向後適用，本節前述各碼不動）

```
格式：<記錄號><用途字母><序號>
  用途字母：R 殘留｜F 不變量・形式｜D 數據缺口｜C 一致性
  例：M14R1、M16F1、O171R1

禁：裸雙字母（MR1）｜單字母＋數字（M1）｜點號式（m14.1）｜prime 循環（F1′）
```

既有 `MR1`–`MR8` 保留（grandfather），新開項一律 `M14R9` 起算。

### 跨記錄引用寫法

```
引用 O171 殘留 → O171R1（唔用裸雙字母）
引用 M16 殘留 → M16F1（唔用裸雙字母）
引用本記錄殘留 → M14R1（新）／MR1（舊，照 §三 映射）
```
