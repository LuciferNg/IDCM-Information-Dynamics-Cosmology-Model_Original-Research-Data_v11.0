## 一、為何 `emb` 族已死

舊引擎把四波矩陣元寫成 `χ⁴(U) × emb(T,Q)`，`emb` 為整數乘法（raw／choose／falling
三公約並存於 `scripts/48_fifth_order.py`，見該檔 `LUTE`／`mel55`／`V33`／`3↔5` 四處）。

以**算子代數**直接建矩陣（`H=(1/4!)ΣT(a+a†)⁴`，基底張量逐項讀精確係數）得：

```
⟨(1⁴,2)|H|(1,1,1)⟩  ×√n = 14 ／ 18
⟨(1,1,2,2,2)|H|(1,1,1)⟩ = 15 ／ 15 ／ 5
⟨(1,1,1,2,3)|H|(1,1,2)⟩ = 2.5 ／ 4.5 ／ 4.5       ← 半整數
⟨(1,1,1,1,2)|H|(1,1,1)⟩ = 48×3
⟨(1⁵)|H|(1,1,1)⟩        = 90（每通道）
另見 75/4 = 18.75
```

**半整數（2.5、4.5、18.75）證明**：任何「整數 `emb` 乘 `χ⁴`」皆不可能等於精確值 ⟹
`raw`／`choose`／`falling` 三者齊否，非單一公約之誤。

交叉證據（數值）：以 `docs/44` 錨 `E_3(n=1)=36.905182722448` 為試金石，
`raw` 命中（36.905182722448）、`choose` = 18.896434702001、`falling` = 44.008209750001，
後兩者兼失對稱 ⟹ 舊引擎連自洽都做不到。但**錨本身亦建於 `χ⁴×emb`**，故「`raw` 命中」
不等於正確——它只是三者中最接近者。

## 二、精確矩陣元（Wick 分解，已封）

```
H = (1/4!)[ :A⁴:_{χ⁴} + 6·Σ_c :A_c²: + 3·N_d ]

mult  = 4!/∏_v c_v(U)! × ∏_v C(c_v(U), c_v(A))  =  4!/(∏_v c_v(A)! · ∏_v c_v(C)!)
NO    = √(∏_v c_T(v)!/(c_T(v)−a_v)!) · √(∏_v c_Q(v)!/(c_Q(v)−q_v)!)
⟨Q|:A⁴:|T⟩ = χ⁴(U) · mult · NO / 24
```

`U = A ⊎ C`（湮滅多重集 ⊕ 創造多重集），`C = Q − (T − A)`。

**閘 G1（本檔 §1）**：3→5 扇區、`N=6` 全枚舉
`14,112/14,112` 逐點 0 差，`max 差 1.388e−17`（機器精度）。

**閘 G2（承前）**：3 模空間 A／B 兩讀法各建矩陣，`3,136/3,136`、`0 差`。

**向量化引擎**（`vertex_apply`）六扇區對參考實作：

```
3→5  5.551e−17 ✅    3→3  5.551e−17 ✅    1→3  0.000e+00 ✅
5→5  2.776e−16 ✅    5→3  1.110e−16 ✅    5→7  1.665e−16 ✅
```

過程中修掉四個真 bug（皆會靜默偏差）：`c_S` 誤用 `c_T`、位置組合重複計入（須除
`∏C(c_T,a)`）、`c!(A)` 只當 1/2（漏 3!／4!）、驗證閘用字典序對 rank 序。

## 三、收縮張量（44 模，精確整數）

```
T2(c,d) ≡ Σ_a χ⁴(a,a,c,d) = δ_cd
   990 對中恰 44 個非零，全部對角，每值 +1.000000000000
   非對角 max 0.000e+00
T0 ≡ Σ_ab χ⁴(a,a,b,b) = +44.000000000000 = N_d
```

結構原因：`T2` 之帶號和為 `a−a−c+d = d−c`，非零 ⟺ `d ≡ c (mod 90)`，故只餘對角。

## 四、兩讀法（使用者裁示：Fork 成兩條路，路徑不重疊）

```
路徑 A（正規序）：頂點只含 :A⁴:；Wick 收縮歸 H_0
路徑 B（保留收縮）：頂點另含同模 Δ=±2 通道；對角位移入 H_0
    Δ=+2：(1/4)√((c_T+1)(c_T+2))，Q = T ⊎ {m,m}
    Δ=−2：(1/4)√(c_T(c_T−1))，    Q = T ⊖ {m,m}
    對角：N_T/2 + 3N_d/24 = N_T/2 + 5.5
```

兩路徑共用同一幾何、同一 `χ⁴`、同一截斷；輸出分別落 `outA/`、`outB/`，互不引用。

## ⚠ 用語更正：O38 錨 = `M₀`（κ 標度），非「`g₄` 錨」（2026-11-23，依調律者校正）

```
原文（§本文件、docs/42–46、docs/41 等）寫「g₄ 絕對標度屬 O38 錨」——措辭把「標度之錨」與「g₄」黏埋，易誤讀成 O38 提供一個「g₄ 錨」。正確身份：

O38 = κ 數值／耦合強度之標度錨（`open_problems_fresh/o38_kappa_prediction`）
      κ² = M₀·ω_scale ⟹ O38 之實質內容 = `M₀`（質量單位標度）錨
g₄  = RS 級數之【無量綱展參】：本 O 只定其係數與界（|g₄| 之上界、翻轉值），
      其「絕對標度」並非另一個獨立錨 —— 一切絕對標度經 M₀ 換算

⟹ 本 O 殘留項應表述為：「絕對標度缺口 → O38／`M₀`（κ 錨）」，而非「g₄ 錨缺口」。
   缺口實質 = M₀ 之絕對值未由結構定出（O38 側），與 g₄ 之係數結構無關。
```

原文不改（append-only）；本節為權威措辭，後續引用以此為準。
