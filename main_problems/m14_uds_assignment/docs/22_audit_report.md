## §十五 工具 bug（本輪第 6 個）：e-記法正則誤吞 md5 十六進位

> append-only。此節只記機制，不含新數值（避免再動 `scripts/37` 之 token 集）。

**症狀**：`scripts/37` 崩潰 —— `OverflowError: int too large to convert to float`。

**根因**：`ENOT = (\d+(?:\.\d+)?)[eE]([-+]?\d+)` 對**無小數點**之字串亦匹配；本節前身（§十四）嵌入 log 之 md5（十六進位），其中片段如 `3e485897` 被讀成「3 × 10 的 485897 次方」。

**影響分兩層**：
```
顯性：指數超界 ⟹ float 轉換拋 OverflowError ⟹ 腳本 rc=1（大聲失敗，易察覺）
隱性（更危險）：若 hex 片段之指數較小（例如 `1e12` 型），會被當成合法科學記法
                ⟹ 產生一個假 token，可能造成假 UNTRACEABLE 或（更壞）假追溯
```

**修法**（本地 `scripts/37` ＋ 共用 skill `reverse_numeric_coverage.py` 同步）：
```
① 先 int() 再判界：|指數| > 400 ⟹ 判為 hex 碎片，原樣返回不轉換
② try/except (OverflowError, ValueError) 兜底
③ 負號仍保留（不清除），故 D2 之符號辨識力不變
```

**驗**：`_enot('3e485897') = '3e485897'`（不轉換）；`_enot('1.578e-4') = '0.0001578'`（正常）。
修後 `scripts/37`：token 156 個、未追溯 0、兩跑 IDENTICAL；audit 復原至 FAIL 0。

**教訓**：正則化「科學記法」時，必須假設輸入含 hex／ID／hash。任何以 `[eE]` 作分隔符之 pattern 都應加指數界。
